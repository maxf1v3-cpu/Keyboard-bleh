# Classic Keyboard

A clean-room Android input method inspired by the compact, classic Gboard 6.8-era layout. It is a new implementation; it does not patch or redistribute Google's APK, code, icons, or proprietary language engines.

## What is included

- Classic QWERTY layout with a suggestion strip, shift/caps-lock, delete, space and editor-action keys.
- Number/symbol page and a basic emoji panel.
- Long-press accented vowels and `n`/`c`/`y`.
- Long-press delete repeat.
- English (US) offline suggestions and conservative one-edit autocorrection.
- Lightweight offline glide-typing approximation.
- Light, dark and follow-system themes.
- Optional system click sounds and short vibration.
- Input-type handling for password fields, numeric fields, email/URI fields and multiline editors.
- Android 16 target (API 36), with modern edge-to-edge handling in the app's activities.

## Privacy and dependencies

The installed application declares **no `INTERNET` permission**. It does not include Google Play Services, Google APIs, Firebase, analytics, crash reporting, cloud sync, remote speech recognition, online search, online translation, or remote language models. It does not store typed text. The included English word list is read locally from the app assets.

The build downloads Android Gradle Plugin from Google's Android Maven repository and Android SDK components from Google's SDK repository. Those are build-time tools only; they do not add Google APIs or network functionality to the installed keyboard.

## Build automatically on GitHub (recommended)

This repository includes `.github/workflows/android.yml`. GitHub Actions will build the debug APK and attach it to the workflow run as an artifact.

1. Download and extract this project ZIP on your computer.
2. Create a new **empty** repository on GitHub. Do not add a README, license, or `.gitignore` during repository creation, since those files are already included here.
3. Upload the **contents** of the extracted `ClassicKeyboard` folder to the top level of your repository. The `.github` folder must be included; it contains the workflow. Make sure GitHub does not end up with an extra `ClassicKeyboard/ClassicKeyboard/` nested folder.
4. Commit the files to the `main` branch (or `master`).
5. Open the repository's **Actions** tab. Select **Build Android APK**. The workflow also runs automatically on pushes and pull requests to `main` or `master`.
6. When the run finishes successfully, open that run and find **Artifacts** near the bottom. Download `classic-keyboard-debug-apk` and extract it. The APK inside is `app-debug.apk`.
7. Transfer the APK to your Android device and install it. Android may ask you to allow installation from the app you used to open the APK.

You can also start a build manually: **Actions → Build Android APK → Run workflow**.

The workflow uses JDK 17, Android Gradle Plugin 9.4.0, Gradle 9.6.0, and Android SDK Platform 36 / Build Tools 36.0.0. It runs the included source checks before building. The generated debug APK is for testing and is signed with a temporary debug key generated by the Android build system. The uploaded artifact is retained by GitHub Actions for 14 days; run another build to produce a fresh artifact after it expires.

### If the GitHub build fails

Open the failed workflow run, expand the red failed step, and copy the **first actual error message** plus roughly 20 lines around it. The final `BUILD FAILED` line alone usually does not identify the cause. Do not send GitHub access tokens, signing keys, or other secrets.

## Build locally on Windows

1. Install Android Studio and, in **Tools → SDK Manager**, install **Android SDK Platform 36**. Android Gradle Plugin 9.4.0 uses Build Tools 36.0.0 by default.
2. Make sure Android Studio's JDK 17 is available, or set `JAVA_HOME` to a JDK 17 installation.
3. Run `Build Debug APK.bat`. It uses Gradle 9.6.0 if already installed; otherwise it downloads Gradle 9.6.0 once.
4. The debug APK will be written to `app/build/outputs/apk/debug/app-debug.apk`.

You can also open the project folder in Android Studio and let it sync the Gradle project.

## Enable it on the phone

1. Install the debug APK.
2. Open **Classic Keyboard**.
3. Tap **1. Enable Classic Keyboard** and enable it in Android's keyboard settings.
4. Return to the app and tap **2. Select Classic Keyboard**.
5. Choose **Classic Keyboard** in the system picker.

Android displays a standard system warning when enabling any third-party keyboard. This app does not transmit keystrokes; the manifest has no network permission.

## Current limitations

This first clean-room version is not a feature-for-feature clone of Gboard. It provides the core on-device typing flow, but omits voice typing, Google search, translation, cloud personalization, clipboard history, stickers/GIF search, multilingual layouts and Google's proprietary next-word prediction. English suggestions and autocorrection are intentionally simple and local. Glide typing is an approximation, not Gboard's gesture-recognition model. The canvas-based keys do not yet provide full per-key TalkBack virtual-node navigation. These limitations should be considered before making it the device's only keyboard.

The project source has been statically checked for valid XML, balanced Java syntax structure, dictionary integrity, and absence of the `INTERNET` permission. A successful GitHub Actions build will confirm that it compiles. It has **not** been installed or tested on a physical Android 16 device yet; keyboard behavior should be tested before relying on it as the only input method.

## Dictionary attribution

`app/src/main/assets/words.txt` is an English word list extracted from the Debian `hunspell-en-us` SCOWL dictionary. Its full attribution and license text are in `licenses/SCOWL_WORDLIST_LICENSE.txt`. `common_words.txt` supplies a short ranking list used by the local suggestion engine.
